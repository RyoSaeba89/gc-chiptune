TOO HEAVY -- 1 file

The file is healthy and plays perfectly on a PC. It is the GEKKO that cannot
keep up: the render takes longer than the duration it produces.

The criterion is the projected MEAN, not the maximum. A maximum above 1000 on
a low mean is a spike, and the ~340 ms of queue absorb it. A mean above 1000
is a permanent deficit: no buffer catches it up, the track falls over from
start to finish.

Projection anchored on the only console measurement available -- HoG - Spec
Ops, host x24.3 -> 1029 per mille mean, 1232 maximum
(docs/TEST-HARDWARE.md). The next one in the corpus is at 801 mean: there is
no borderline case, there is this file and all the others.

  HoG\HoG - Spec Ops The Line +4 trn.v2m
      projected mean 1029 per mille (1000 = limit) -- host x24.3
